# Версии каркаса Jericho

Что менялось — по версиям, свежие сверху. Подробности версии — в сообщении её коммита: `git show vX.Y.Z`.
Проект берёт каркас по тегу (`jericho-ai @ git+https://github.com/Anach0ret/jericho-ai@vX.Y.Z`); правило записи —
одна строка на версию: что стало можно или как стало работать, словами пользователя каркаса.

## 2026-11-08

- **0.64.13** — остановка дерева программ находит потомков через `psutil`, а не `/proc`: на macOS — как на Linux (внук со своей группой больше не переживает остановку), на Windows — работает (всё дерево сразу, отделённое не различается — `docs/security.md` «Платформы»); `stop` на Windows завершает процесс фразы сразу
- **0.64.12** — ручки работают на Windows: срок ручки там — прерывание главного потока (`InterruptTimer`, сигнал `SIGBREAK`; Ctrl+C остаётся остановкой фразы), исполняющийся Python-код обрывается, блокирующая операция — после своего конца, ей нужен свой таймаут; на Linux и macOS — `SIGALRM`, как было; `jericho.E015` на Windows проверяет, что папки ассистента в профиле пользователя, а не биты chmod; в README, `stability.md` и `security.md` — «Платформы»: разработка на любой ОС, полные гарантии — Linux
- **0.64.11** — вывод программ, которые запускает ручка, читается в UTF-8 на любой ОС (битый байт заменяется, а не роняет вызов); ввод команд — тоже UTF-8; пути в сообщениях `check` — с «/» на любой ОС; на Windows ставится база часовых поясов `tzdata`, а журнал, занятый другим процессом, сменяется в следующий раз, а не роняет фразу
- **0.64.10** — замок не остаётся занятым, если не удалось записать или убрать файл с номером держателя: ошибка уходит дальше, а замок освобождается; проверка macOS/Windows «импорт без extras» — действительно без группы dev
- **0.64.9** — команды каркаса и проекта пишут вывод в UTF-8 на любой ОС: на Windows перенаправленный вывод (в файл, трубу, CI) больше не падает на русском тексте; тесты зовут программы по имени, а не по пути Linux, тест терминала и тест D-Bus — только там, где они есть
- **0.64.8** — замок файла (фраза, планы, памятки, задачи, голос) — пакет `filelock`, на любой ОС; номер держателя — рядом, в `<замок>.pid` (на Windows занятый замок не прочитать); стандартные папки на macOS и Windows — по правилам этих ОС (`platformdirs`), явные `XDG_*` главнее везде, на Linux пути прежние; `startproject` пишет путь к каркасу из исходников с «/» (TOML на Windows)
- **0.64.7** — README и `docs/stability.md` говорят точно, что держит каркас на Linux: ядро задумано без привязки к ОС, но пока использует механизмы POSIX (на Windows не запускается, на macOS не проверялось); голос, уведомления по D-Bus и задачи на systemd — необязательные батарейки под Linux
- **0.64.6** — каркас открыт: публичный репозиторий `Anach0ret/jericho-ai`, команды установки и `Repository` в `pyproject.toml` (оттуда `startproject` берёт адрес) — на него. Первая публичная версия — эта

## 2026-11-07

- **0.64.5** — программа `core.runner.run()` без переданного ввода получает пустой stdin, а не терминал ассистента: запущенный из консоли ассистент больше не ждёт до срока программу, которая попробовала прочитать ввод (после 0.64.4 она замирала на SIGTTIN)
- **0.64.4** — отделённое `launch()` отличается от синхронного `run()` по сеансу процесса, а не по метке в окружении: браузер или приложение, очистившее окружение (`env -i`) или закрывшее его чтение (песочница), тоже переживает остановку вызывающего процесса; переменной `JERICHO_DETACHED_LAUNCH` больше нет
- **0.64.3** — запущенные через `launch()` браузер, приложение или план продолжают работать, если остановился вызвавший их процесс; синхронный `run()` вместе с потомками по-прежнему останавливается
- **0.64.2** — **Строже:** остановка программы достаёт всё дерево потомков, и вложенный запуск со своей группой тоже (ответ inbox → `claude` → сервер ручек → программа ручки), а KILL уходит, даже если паузу после TERM прервал срок ручки; план, запущенный ручкой `plan_run`, и перезапуск без человека не наследуют срок исходной фразы — у каждого шага свой
- **0.64.1** — примеры настроек в README и docs переносятся в `class Base(Settings)` как есть (поля с аннотациями — их проверяет тест, целые примеры собираются); пример EFFECT-ручки называет `approval` (E008); публичный снимок сохраняет исполняемый бит хука; CI ставит wheel, собранный из sdist, в чистое окружение без dev и extras и проверяет на нём проект из образца; команды установки — на `v0.64.1`
- **0.64.0** — **Строже:** у фразы один срок (`agent.timeout`) на всё: после него ни одна ручка не начинается — отказ `phrase_deadline_passed`, в том числе на сервере ручек `claude_cli`/`codex_cli` (срок приходит ему переменной `JERICHO_DEADLINE`) и через `confirm`; запасной бэкенд, следующая модель OpenAI и программа модели работают в остатке срока, а не в новом полном; программа, которую ручка запустила через `core.runner`, при сроке, обрыве ручки или Ctrl+C останавливается вместе со всеми своими потомками (группа процессов, TERM → KILL), так же — ответ из ящика `inbox`
- **0.63.0** — **Строже:** `state_name` — одно простое имя папки (буквы, цифры, `.`, `_`, `-`, не с точки): иначе вариант «вхолостую» мог указать на рабочую папку другой строкой (`same/.`); «вхолостую» `timers install` и `remove` не пишут и не удаляют unit-файлы (только журнал), а `web_search` — всегда офлайн, квота поисковика не тратится; `plans --run` (и `plan_run`) перезапускает себя без человека до сборки, как `task`: действие с последствиями без «да» в нём — отказ `nobody_to_ask`, вопросы не ложатся ждать
- **0.62.1** — **Строже:** распаковка не вынесет `.env` через цепочку жёстких ссылок (`three → two → one → .env`) — отбрасывается вся цепочка; упаковка пишет архив в занятый ею файл, а при сбое не удаляет файл, которым тем временем подменили путь; `<проект> plan-create` принимает шаги обычными строками; `CoreServices.own_paths` перенесён в конец — позиционный вызов 0.57.0 снова передаёт `user`; тесты замков планов и памяток идут через собранный модуль
- **0.62.0** — **Строже:** «да» относится к тому вопросу, который пользователь видел: строку вопроса «<что сделать>? Да или нет.» ставит код из записанного вызова, слова модели — подробностями под ней; ответ без вопроса или новый вопрос модели в следующей фразе снимает ждущий; кнопка «Да» в уведомлении несёт id вопроса и сменивший его вопрос не подтвердит (транспорт чата — поле `confirm_id` в ответе, `answers` в запросе); если с вопроса всё изменилось, «да» даёт новый вопрос, а не «не сделано»; пользователь с пределом `user_risk` может подтвердить то, что ему разрешено (`confirm` проверяется по подтверждённой ручке — `Tool.relays`)
- **0.61.0** — **Строже:** одинаковое имя ручки у ядра, модуля или навыка — ошибка сборки с указанием обоих; отложенное поручение, от которого ассистент отказался, — `refused` и неуспешный запуск, а не «выполнено»; ручной вызов ручки из терминала понимает «нет»/«false» (`--x`/`--no-x` у необязательных), списки и JSON для сложных полей; `read_file` дочитывает длинную строку (`next_offset`); `run_script` отдаёт модели все шаги смешанного сценария по порядку; планы и памятки не теряют изменений, сделанных одновременно из окна и фразы; ответ Anthropic с неверным входом вызова не выполняется и не роняет фразу; выбор модели работает без раздела бэкенда в настройках; E003 видит относительные импорты; генератор навыков не ломается на кавычках в описании и не принимает слова Python как имена
