# Проверки структуры

`<проект> check` — правила, по которым устроены ядро и навыки проекта. Замечание — это нарушение правила:
команда завершается с кодом 1. Проверки читают код как текст и смотрят на уже собранные навыки; модель и
оконный менеджер им не нужны.

| Код | Правило | Зачем |
|---|---|---|
| `jericho.E001` | у навыка есть `skill.py`, `SKILL.md`, `tests/` и хотя бы одно из двух: ручки (`tools`) или белый список (`allowlist.py`) | навык без текста для модели или без ручек — не навык |
| `jericho.E002` | навык импортирует только себя и открытые имена ядра: `from jericho.core import …` | чужой навык, глубина ядра, сборка и настройки проекта навыку недоступны; общее для двух навыков переезжает в ядро. Тестам навыка разрешены `jericho.core.testing` и части ядра, которые они собирают. Относительные импорты (`from ..other import x`) разбираются так же |
| `jericho.E003` | ядро не импортирует ни модули и бэкенды каркаса, ни навыки, ни пакет самого проекта | ядро не знает, какие навыки и какой проект подключены |
| `jericho.E004` | `pydantic` не импортируется в `entities`, `protocols.py`, `application/` (и прежней `services/`) навыка | `pydantic` — на границах, где данные приходят снаружи; внутри — `dataclass` |
| `jericho.E005` | навык не импортирует `subprocess` | программы запускаются через `core.runner`: один таймаут, одна запись в журнал, один режим «вхолостую» |
| `jericho.E006` | каждая ручка из `tools/` и каждый белый список из `allowlist.py` вписаны в `tools()` навыка | список ручек явный, как `urlpatterns`; забытую ручку модель не увидит |
| `jericho.E011` | раздел промпта подключённого модуля (`<пакет>:prompt.md`) назван в `PROMPT_SECTIONS`, а неподключённого — не назван | забытый раздел — модель не знает, как пользоваться ручками модуля; раздел без модуля — читает про ручки, которых нет |
| `jericho.E010` | общий промпт описывает каждое поле выбранной формы ответа (`agent.reply_form`) | форма и раздел о формате называются в настройках отдельно и могут разойтись |
| `jericho.E009` | служба (`<проект>/services/<имя>/`) импортирует только себя и открытые имена ядра | служба — общий слой под навыками: зависимости идут от навыка к службе и никогда обратно |
| `jericho.E008` | каждая ручка навыка и модуля объявляет класс риска: `risk = Risk.READ`, `NAVIGATE`, `CHANGE` или `EFFECT`; у белого списка — `risk=` в его объявлении; у ручки `EFFECT` ещё и `approval = Approval.ASK` или `Approval.TOOL` | необъявленный класс считается самым опасным, но он должен быть выбран, а не достаться по умолчанию: его читают модель и проверки. Кто спрашивает «да» перед действием с последствиями — тоже выбор, а не умолчание |
| `jericho.E007` | у каждой подстановки `{{имя}}` в `SKILL.md` есть источник в `contexts()` навыка | иначе в руководстве навыка окажется пустое место |
| `jericho.E012` | класс каждой ручки навыка используется в коде его тестов — не в комментарии и не в одном импорте (белые списки не в счёт) | ручку без теста агент сдал бы непроверенной; правило видит, что тест есть, а не что он проверяет нужное |
| `jericho.E015` | в папках ассистента — файлы машины (`~/.config/<проект>`), состояние, сеанс — ничто не открыто группе и остальным (замки не в счёт) | там ключи API, сессия Telegram (полный доступ к аккаунту), журнал и разговор; каркас сам создаёт файлы `600` и папки `700`, правило ловит созданное руками и программами. **На Windows** биты chmod не значат ничего (права — ACL) и не проверяются: правило проверяет только, что папки лежат в профиле пользователя — его Windows закрывает от других учётных записей |
| `jericho.E014` | шаг-ручка сценария (модуль `scripts`) называет существующую ручку, параметры проходят её схему, класс ручки не EFFECT | опечатка в сценарии видна в `check`, а не по нажатию кнопки; «да» на действие с последствиями в сценарии спросить не у кого |
| `jericho.E013` | в службе нет ручек: ни наследников `Tool`, ни белых списков | модель о службе не знает, ручку службы некуда подключить — это код не в том слое |
| `jericho.E016` | модуль `inbox` с несколькими пользователями (`inbox.users`) и бэкенд по подписке — Claude (`claude_cli`) или ChatGPT (`codex_cli`), основной или запасной — не сочетаются | условия Anthropic и OpenAI: подписка — для личного использования её владельцем; другим людям — бэкенд по ключу |

Новый навык и новую ручку создают заготовки: `<проект> startskill <имя>` и
`<проект> starttool <навык> <ручка>`. Заготовка навыка проходит все правила сразу; о ручке, которую
забыли вписать в `tools()`, напомнит E006.

Навык может добавить свои правила: метод `checks()` в `skill.py` возвращает объекты с методом
`run(project) -> list[CheckMessage]` — их удобно держать в `checks.py` навыка.
