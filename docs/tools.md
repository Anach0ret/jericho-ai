# Договор ручки

Ручка — действие, которое может вызвать модель (tool в MCP). Здесь написано, что ручка объявляет, что за неё
гарантирует каркас и что остаётся на ней самой. Создать ручку: `<проект> starttool <навык> <ручка>`.

## Что ручка объявляет

Всё объявляется в её классе, рядом с кодом. Отдельной копии описаний нет: бэкенд и командная строка строят схему
из класса.

| Что | Где в классе | Обязательно |
|---|---|---|
| имя | `name` | да |
| описание | `description = ToolDescription(when, does, returns, refusals)` — **Когда** → **Что делает** → **Вернёт** → **Отказы** (коды) | да |
| параметры | `request_type` — наследник `ToolRequest`; у каждого поля описание, ограничения — в объявлении; лишние поля запрещены | да |
| класс риска | `risk = Risk.READ` · `NAVIGATE` · `CHANGE` · `EFFECT` — по самому тяжёлому, что ручка умеет | да (E008) |
| кто спрашивает «да» | `approval = Approval.ASK` (каркас, перед каждым вызовом) или `Approval.TOOL` (сама ручка, через `ConfirmationGate`) | у `EFFECT` — да (E008) |
| вопрос пользователю | `consent_summary(arguments)` — что прозвучит в вопросе, если спрашивает каркас | нет: по умолчанию имя и параметры |
| служебная ручка | `service = True` — обслуживает работу, а не делает дело | нет |
| доказательство заметки | `proves = {"url": "address"}` | нет |
| выносит наружу | `outbound = True` — открывает адрес, отправляет, скачивает, ищет в интернете; после личных данных в этой фразе — только с «да» | нет |
| отдаёт файлы с машины | `local = True` — модель получает содержимое файлов пользователя (`read_file`); вызывать может только бэкенд из `agent.private_backends` (без списка — основной); если в той же фразе был и чужой текст, вынос наружу — только с «да» | нет |
| личные поля | `private = ("messages", "text")` — поля параметров и ответа с чужой перепиской: в журнал не пишутся («скрыто: N знаков»), модель получает их целиком; ручка кладёт в ответ `memo` — что сделано без текста, его и запомнит разговор и журнал фраз (полный ответ — в папке сеанса, уведомление — без истории); те же поля скрыты в аварийной записи и в вопросе «да», который задаёт каркас; вызывать такую ручку может только бэкенд из `agent.private_backends`, а без списка — только основной; запасная модель получает отказ `private_needs_trusted_model`. Ручка, которая отдаёт ответ другой ручки (как `confirm`), называет её поля в `private_in(result)` | нет |
| передаёт чужой вызов | `relays = True` — ручка только передаёт уже записанный вызов тому же диспетчеру (`confirm`): предел пользователя (`user_risk`) проверяется у того вызова, а не у неё | нет |

| Класс | Что значит | Пример |
|---|---|---|
| `READ` | только читает, ничего не меняется | список окон, текст страницы |
| `NAVIGATE` | открывает и переключает; вернуть как было — одно действие | открыть сайт, переключить вкладку |
| `CHANGE` | меняет состояние, но поправимо | громкость, раскладка окон, заметка |
| `EFFECT` | последствие не отменить или оно уходит наружу | закрыть окна, нажать «Отправить», отправить письмо |

## Что гарантирует каркас

Вызов от модели идёт только через `ToolDispatcher`: у бэкендов `claude_cli` и `codex_cli` его делает сервер ручек, у бэкендов
по ключу и у `scripted` — процесс поручения, у `confirm` — тот же диспетчер.

| Ситуация | Что делает каркас | Где |
|---|---|---|
| параметры не по схеме | отказ `invalid_parameters` со списком «поле — что не так»; ручка не вызывается | диспетчер |
| ручка навыка до `load_skill` | отказ `skill_not_loaded` | слой `RequireLoadedSkill` |
| `READ`, `NAVIGATE`, `CHANGE` | пропускает | политика риска |
| `EFFECT`, `approval=ASK`, человек рядом | записывает вызов и отказывает `needs_confirm`; выполняет только `confirm()` в **следующей** фразе, если пользователь сказал «да» (его слышит код, не модель), — ровно записанный вызов; «да» забирается один раз | политика риска, `PhraseConsent` |
| `EFFECT`, `approval=TOOL`, человек рядом | пропускает: когда спрашивать, решает ручка | политика риска |
| `EFFECT` без человека (задача по расписанию) | отказ `nobody_to_ask` до ручки, при любом `approval`; исключение — ручки, названные проектом в `unattended_effects` | политика риска |
| «вхолостую» (`DryRun`) | меняющие команды через `runner` не выполняются, а пишутся в журнал; unit-файлы таймеров не пишутся и не удаляются; поиск — офлайн; вопросы задаются как обычно | `DryRunRunner`, модули `tasks`, `search` |
| ручка дольше `tool_timeout` | обрывается; модель получает `tool_timeout` с пометкой «что успело произойти, неизвестно — не повторяй» | диспетчер |
| исключение в ручке | модель получает `tool_failed` и имя класса, без текста; трассировка — в журнал | диспетчер |
| каждый вызов | запись в журнал: ручка, параметры, итог, время | слой `Journal` |

Политику риска нельзя убрать настройками: она не слой из `TOOL_MIDDLEWARE`, а часть диспетчера. Вызов ручки
руками из терминала (`<проект> <ручка> …`) идёт без неё: команду набирает сам человек.

## Что остаётся на ручке

- **Защита от повторов и неизвестный исход.** Каркас гарантирует, что «да» на вызов будет забрано один раз: второй
  `confirm()` его не найдёт. Что внешнее действие случилось ровно один раз, это не гарантирует.
  Если ручка упала посередине, обрыв по сроку или остановка пришлись на её работу, каркас не знает, случилось ли
  действие. Ручка, у которой повтор опасен (отправка, оплата), сама проверяет, сделано ли уже, или делает
  действие идемпотентным, например по ключу из параметров.
- **`approval=TOOL`.** Ручка обязана сама спрашивать «да» там, где действие опасно, и передавать `subject` —
  что именно она тронет. Иначе «да», данное на другое, сработает на изменившееся. Обычно это одна строка:
  `require_consent(gate, self.name, arguments, summary, subject, **подробности)` из `jericho.core` — согласия
  ещё нет, и она бросает отказ `needs_confirm` с `summary`, подробностями и пометками службы (`changed`,
  `replaced`, `nobody`). `gate.consent(…)` напрямую — только если без согласия ручка делает что-то другое.
- **Чужой текст.** Ручка, которая отдаёт модели текст не от пользователя (страница, письмо, выдача поиска), зовёт
  `core.foreign.read_from(источник)`. Ручки, которыми может воспользоваться внедрённая в такой текст команда,
  смотрят `core.foreign.sources` и после такого чтения спрашивают «да».
- **«Вхолостую».** Адаптер, который действует не через `core.runner` (браузер, сеть), сам смотрит `core.dry_run`.
- **Запреты своей области** — какое окно своё, какое слово нельзя нажимать — держит ручка и её навык.

## Ответ ручки

`ToolResult.success(**данные)` или отказ `raise ToolRefusal("код", **подробности)`. Код короткий и стабильный,
по нему модель решает, что сказать: `not_found`, `ambiguous` + `candidates`, `needs_confirm`. Подсказка
к отказу (`candidates`, `allowed`) даёт модели исправиться за один повтор.

Посмотреть описание так, как его видит модель: `<проект> <ручка> --help` или `<проект> prompt <навык>`.

## Ходы модели, которых можно избежать

- **«Да» и «нет» — без модели** (`agent.consent_without_model`, включено по умолчанию). Ответ на ждущий вопрос
  распознаёт код; на «нет» вопрос снимается и ответ «Отменил: …» собирает код, на «да» код выполняет ровно
  подтверждённый вызов (как ручка `confirm()`) и отвечает его итогом: `detail` из ответа ручки, иначе «Сделано: …».
  Ручке с долгим делом стоит возвращать `detail` — его и услышит пользователь. Если с вопроса всё изменилось
  (ручка снова ответила `needs_confirm`), ответ — новый вопрос (`clarify`), и следующее «да» относится уже к нему.
- **Текст вопроса «да?» — от кода.** Ответ `clarify` фразы, где ручка задала вопрос, начинается строкой
  «<summary>? Да или нет.», слова модели — подробностями под ней; ответ без вопроса или новый вопрос модели в следующей
  фразе снимает ждущий. Кнопка «Да» несёт id вопроса (`PendingConfirmation.id`) и сменивший его вопрос не подтвердит.
- **Руководство навыка — в общем промпте** (`PRELOADED_SKILLS = ("server",)`). `load_skill` для такого навыка не
  нужен, его ручки модель видит с полными описаниями. Подходит ассистенту с одним-двумя навыками: у многих навыков
  промпт вырос бы на все руководства сразу.
