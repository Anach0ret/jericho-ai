# Входящие: ассистент за транспортом

Модуль `jericho.modules.inbox` принимает поручения сообщениями транспорта — например, бота Telegram — и отвечает
ему же. С транспортом ассистента связывает **только папка**: сети, портов и общей базы нет. Транспорту не нужны
ни права на сервере, ни доступ к журналу ассистента.

## Папка обмена

```
exchange/                  inbox.directory
├── inbox/                 транспорт → ассистент: запросы
│   ├── tmp/  new/         пишется / пришло
│   ├── cur/               ассистент взял в работу
│   └── rejected/          чужое или испорченное — не выполнено
└── outbox/                ассистент → транспорт: ответы и сообщения без запроса
    ├── tmp/  new/
```

Это Maildir. Сообщение — файл JSON. Пишется в `tmp/` и переносится в `new/` одним `rename`, поэтому читатель
половинки не увидит. Забрал и отдал — удалил. Имена растут со временем: по имени видно, что пришло раньше.
Реализация на стороне ассистента — `jericho.core.services.mailbox.Mailbox`.

## Сообщения

| Куда | Поля |
|---|---|
| `inbox/` запрос | `id` — свой у транспорта; `user` — кто пишет (Telegram ID); `chat` — куда вернуть ответ; `text`; `answers` — необязательно: `confirm_id` вопроса, под которым нажата кнопка «Да»/«Нет» (с 0.62.0) — тогда ответ засчитается только этому вопросу, сменившийся вопрос получит «уже не ждёт ответа»; `reply_to` — необязательно (с 0.65.0): номер сообщения у транспорта, на которое человек ответил (Telegram reply) |
| `inbox/` квитанция | `receipt` — `notice` сообщения без запроса; `delivered` — дошло ли целиком (`false` — не дошло или не все части); `messages` — номера отправленных сообщений у транспорта (с 0.65.0). Не поручение: модели не идёт, отмечается в журнале отправленного |
| `outbox/` ответ | `id`, `user`, `chat` из запроса; `status` (`done`, `clarify`, `refused`, `ignored`, `failed`, `stopped`); `title` — суть одной строкой; `text` — подробности, может быть пустым ; `confirm` — есть, если ответ кончается вопросом «да?»: что именно подтвердить (транспорт может показать кнопки «Да» и «Нет»; нажатие — это сообщение «да» или «нет»); `confirm_id` — id этого вопроса: верните его в `answers` вместе с нажатием |
| `outbox/` без запроса | `to` — адресат (`owner`); `task` — какое поручение; `status`, `title`, `text`; `notice` — номер (с 0.65.0): на него — квитанция |
| `outbox/` о вопросе «да?» | `chat` и `user` — чей вопрос (в личной переписке номер чата — номер пользователя); `task: "confirmation"`; напоминание — `status: "clarify"`, `confirm` и `confirm_id` (кнопки «Да/Нет»), истёк — `status: "stopped"` |

`id`, `user` и `chat` могут быть числами (как у Telegram) — ассистент читает их строками.

## Что делает ассистент

- Команда `<проект> inbox` — постоянный процесс. Раз в секунду (`poll_seconds`) смотрит в `inbox/new/`
  и берёт сообщения по одному.
- **Пользователь сверяется со списком `inbox.users`**, хотя транспорт уже сверил его со своим: взломанный
  транспорт не получит ассистента. Чужое и испорченное уходит в `rejected/` без ответа.
- **Каждый запрос — отдельный процесс** `<проект> answer` с `JERICHO_USER=<user>`. Он собирается заранее и ждёт путь
  к запросу на stdin (`answer --wait`): сборка ассистента — секунды, и ответ их не ждёт; после ответа следующий
  процесс собирается про запас. У пользователя своя
  папка сеанса: «да» подтверждает только тот, кто спросил, и уточнение не попадёт в чужой разговор. Журнал общий;
  в каждой записи стоит `user`.
- Поручение упало или не уложилось в срок (`agent.timeout` + `answer_margin`) — ответ `failed` пишет сам приём.
  Взятое до перезапуска и не законченное не повторяется (могло уже выполниться): уходит `failed` «ответ прервался».
- Сообщения без запроса — сводки, итоги задач, напоминания — даёт вывод `mailbox`:
  `OutputSettings(kind="mailbox", mailbox=Path("/exchange/outbox"), to="owner")`.
- Что ушло без запроса, записывается в журнал отправленного (`SentLog`, папка состояния, сутки) — для модуля
  `notices`: ответ человека на сводку — о ней (`docs/notices.md`). Транспорт, который шлёт квитанции и `reply_to`,
  даёт точный выбор; без них работает выбор по последним уведомлениям.

## Вопрос «да?» в чате

В чате человек отвечает не сразу, поэтому у ассистента за ботом срок вопроса длиннее, чем у голоса за столом:
`confirmation_minutes` в общих настройках (по умолчанию 2). Пока вопрос ждёт, постоянный приём (`inbox`) раз в 15 секунд
смотрит вопросы пользователей из `inbox.users`:
- вопрос ждёт дольше `inbox.remind_minutes` и «да» ещё не было — **одно напоминание** с кнопками «Да/Нет»
  (0 — не напоминать);
- срок вышел — **«вопрос истёк, ничего не сделано»** и запись `confirmation_expired` в журнал.

«Да» или «нет», пришедшее после срока, тоже получает «истёк» — без модели и без выполнения. Из двух мест — ответ
пользователя и обход — «истёк» достанется одному: вопрос забирается одним переименованием файла.

## Настройки

```python
INSTALLED_MODULES: tuple[str, ...] = (..., "jericho.modules.inbox")
PROMPT_SECTIONS: tuple[str, ...] = (..., "jericho.modules.inbox:prompt.md")
inbox: InboxSettings = InboxSettings(directory=Path("/exchange"), users={"123456789": "владелец"})
```

| Поле | По умолчанию | Что |
|---|---|---|
| `directory` | `~/exchange` | папка обмена с транспортом |
| `users` | пусто — не принимает никого | идентификатор у транспорта → имя для журнала |
| `poll_seconds` | 1 | как часто смотреть в ящик |
| `max_text` | 4000 | длиннее — отказ `refused` без модели |
| `answer_margin` | 30 с | сколько ждать ответа сверх срока фразы |

## Права пользователей

Все из `inbox.users` могут писать, но действовать — не все. Предел риска на человека — в настройках каркаса:

```toml
user_risk = { "123456789" = "effect" }   # владелец: всё, с «да»
default_user_risk = "read"               # остальные: только читать (по умолчанию)
```

Ручка выше предела получает отказ `not_allowed_for_user`, и «да» его не снимает: проверяет политика риска
диспетчера, до вопроса. Предел берётся по `JERICHO_USER` — тому, чей запрос исполняет процесс.

## Что остаётся транспорту

- Свой белый список пользователей, предел длины и частоты сообщений.
- Сопоставить ответ с запросом по `id`, адресата `owner` — со своим идентификатором владельца.
- Права на папку: транспорт и ассистент пишут в `exchange/` от одного uid (в контейнерах — 1000).
