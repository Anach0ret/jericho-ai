# Модель безопасности

Что каркас гарантирует, кто за это отвечает и чем это проверено. Таблица появилась по ревью кода 16.10.2026.

## Две модели доверия

Каркас рассчитан на **первую**.

1. **Автор навыка доверенный, ограничивается модель.** Код навыков пишет человек или агент, а человек его читает
   и принимает. Каркас не даёт модели выйти за рамки: она выбирает действие, а разрешение решает код. Для этого
   случая гарантии ниже держатся.
2. **Навык пишет агент без проверки человеком.** Код на Python может всё: импортировать стандартную библиотеку,
   ходить в сеть и к файлам мимо `CoreServices`. Проверки `check` ловят типичные ошибки, но не ограничивают
   полномочия процесса. Для такого случая нужна граница исполнения: отдельный процесс с ограниченными правами
   и проверяемый договор расширения. **Этого в каркасе нет.** Пока работает правило: навык, написанный
   агентом, принимает человек, и `check` ему в этом помощник, а не замена.

## Инварианты

| Инвариант | Кто держит | Механизм | Чем проверено |
|---|---|---|---|
| Действие с последствиями (`EFFECT`) без согласия пользователя не выполняется | каркас | `RiskPolicy` внутри `ToolDispatcher`: при `approval=ASK` спрашивает каркас, при `TOOL` — ручка | `tests/core/test_risk_policy.py` |
| Согласие даёт пользователь, а не модель | каркас | `PhraseConsent`: «да» и «нет» на ждущий вопрос распознаёт код по самой фразе, до модели; `grant()` отдаёт только вопрос, одобренный своим запуском | `tests/core/test_confirmation.py` (`TestYesIsHeardByCode`) |
| «Да» — на тот вопрос, который пользователь видел | каркас | `AskedQuestion`: текст вопроса — из записанного вызова, а не слова модели; ответ без вопроса или новый вопрос модели снимает ждущий; кнопка (голос, чат) несёт id вопроса, сверка — под замком фразы (`PhraseConsent.hear(…, question)`) | `tests/core/test_consent_binding.py` |
| Согласие — на названный объект | ручка (`subject`) + каркас (сверка) | `ConfirmationGate.consent(…, subject)`: объект изменился — вопрос заново | `TestConsentIsForWhatWasNamed` |
| Без человека действие с последствиями не выполняется | каркас | `RiskPolicy`: `nobody_to_ask`; разрешение — только поимённо в `unattended_effects` | `test_risk_policy.py`, `modules/tasks/tests` |
| Пробный режим не пишет в рабочее состояние | каркас | у `DryRun` и `Eval` своя папка: сравниваются **итоговые** настройки с файлами машины, а `state_name` — одно простое имя папки (без `/` и `.` в начале: `same` и `same/.` не обманут проверку); `Eval` обязан быть `dry_run`; прогон стирает только внутри своих папок | `tests/core/test_settings.py`, `tests/integration/test_eval_isolation.py` |
| «Вхолостую» внешние команды не выполняются | каркас (`runner`) + адаптер | `DryRunRunner`; адаптер, который действует не через `runner`, смотрит `core.dry_run`: unit-файлы таймеров (`UnitFiles` — ни записи, ни удаления), поиск — всегда офлайн | тесты навыков, `tasks/tests` (`TestDryRun`), `search/tests` |
| Прогон без человека собирается без человека | каркас (`Relaunch`) | `task` и `plans --run`, запущенные с человеком, перезапускают себя с `JERICHO_UNATTENDED=1` до сборки: подтверждение и сервер ручек собираются уже «никого нет» | `tasks/tests`, `plans/tests` (`TestRunWithoutAPerson`) |
| После срока поручения новые действия не начинаются | каркас | один срок на фразу (`PhraseDeadline`, ставит `HandlePhrase`): диспетчер не начинает ручку после него — `phrase_deadline_passed`, кто бы ни звал (цикл по ключу, сервер ручек CLI — срок приходит ему в `JERICHO_DEADLINE`, `confirm`); запасной бэкенд, следующая модель OpenAI и программа `claude`/`codex` получают остаток, а не новый срок; срок ручки — не больше остатка; предел вызовов | `tests/core/test_phrase_deadline.py`, `backends/tool_loop/tests` (`TestBudget`) |
| Прерванная программа не оставляет синхронных потомков | каркас (`runner`), `inbox` | `run()` — своя группа процессов в том же сеансе и пустой stdin, если ввод не передан (терминал из фоновой группы остановил бы программу), `launch()` — свой сеанс; срок, срок ручки, Ctrl+C — останавливается всё дерево потомков в сеансе останавливаемого с их группами (вложенный запуск со своей группой тоже), TERM → 2 с → KILL, KILL — даже если пауза прервана; исходная ошибка идёт дальше; процессы другого сеанса (`launch()`: браузер, приложение, фоновый план) переживают остановку — признак держит ядро, а не окружение программы | `tests/core/test_runner.py` (`TestProcessTree`, `TestLaunchedStaysAlive`), `inbox/tests` |
| Сломанные параметры не превращаются в действие | каркас | `invalid_arguments` до диспетчера; лишние поля запрещены | `test_loop.py`, `openai_api/tests` |
| Чужой текст учитывается, откуда бы он ни пришёл | каркас + ручка | `ForeignText` (+ событие `foreign` в журнале); разговор хранит источники и передаёт их следующей фразе, а её ответ запоминается и с унаследованными — пометка не теряется, когда исходный обмен вышел из памяти разговора; `read_journal` — источник; файлы из корня `untrusted` — источник; ручка `web_search` (модуль `search`) — источник, только когда поиск был; встроенный поиск программы `claude` (`WebSearch`) по-прежнему делает фразу чужой целиком — поэтому его лучше заменить модулем | `modules/dialogue/tests`, `journal_reader/tests`, `files/tests`, `claude_cli/tests` |
| Личные поля (`Tool.private`) не попадают в журнал | каркас | `PrivateFields` — одно правило для слоя `Journal`, аварийной записи диспетчера (у такой ручки — без текста исключения: только вид и строки кода), вопроса «да» каркаса (`consent_summary`) и записи `confirm` (поля — подтверждённой ручки, `Tool.private_in`) | `tests/core/test_tool_middleware.py` (`TestPrivateFieldsEverywhere`) |
| Личные данные — только доверенной модели | каркас | `TrustedModel`: бэкенды из `agent.private_backends`; список не назван — **только основной** (с учётом выбранной модели; серверу ручек — `JERICHO_MAIN_BACKEND`), запасной — если назван явно | `tests/core/test_private_data.py`, `tests/integration/test_bootstrap.py` |
| Прочитанный файл с машины не уходит наружу по команде со страницы | каркас | `Tool.local` → `CallSession.read_local`; правило `OutboundAfterPrivate`: после файла **и** чужого текста в фразе `outbound` — только с «да», без человека — `nobody_to_ask` (аудит 27.10.2026) | `tests/core/test_private_data.py` (`TestOutboundAfterLocalFiles`) |
| Файлы — только внутри корней проекта; запретное (`.ssh`, `.git`, `.env`, ключи) не видно даже внутри них | модуль `files` | `PathGuard`: `resolve()` снимает `..` и ссылки, затем корень и образцы `deny`; ручки строят пути только через него; корней нет — отказ во всём; папки самого ассистента (`OwnPaths`: состояние, сеансы **всех** пользователей, файлы машины, код проекта и каркаса, папка обмена `inbox`) защищены при любых корнях — внутрь ни читать, ни писать; папку, внутри которой они лежат, не скопировать, не упаковать, не переместить и не удалить (отказ целиком, а не пропуск); папку с вложенным корнем `read_only` не убрать; копия, перенос и упаковка из корня `untrusted` в доверенный — только с «да», как распаковка; ссылка в архиве на пропущенное пропускается вместе с ним — и вся цепочка ссылок, которая к нему ведёт | `files/tests` |
| Файл удаляется только после «да» на эти самые записи и только в корзину; правка и замена сохраняют прежнюю версию; после чужого текста в фразе правка тоже ждёт «да» | модуль `files` | `delete` — `Approval.TOOL`, согласие на путь + размер + время изменения; `Trash` (freedesktop или папка состояния); `Versions` перед `replace`; `FileAccess.ask_if_foreign` | `files/tests` |
| Ручка, отдающая чужой текст, отмечает его | **автор навыка** | `core.foreign.read_from(источник)`; можно одной обёрткой (например, вокруг браузера), а не в каждой ручка | **проверки нет** |
| Запрет нельзя собрать из разрешённых ручек | **автор навыка** | например, ручка клавиатуры без букв, пробела и Enter: из неё не собрать набор текста | тесты навыка |
| Ручка с повторами (отправка, оплата) идемпотентна | **автор навыка** | см. `docs/tools.md` | — |
| Каждый начатый вызов имеет известный или явно неизвестный исход | частично | срок → `tool_timeout` «исход неизвестен»; запись о начале вызова в журнале не ведётся | — |

Строки, где держит **автор навыка**, — это дисциплина, а не гарантия каркаса.

## Чего каркас не обещает

- Ровно один внешний эффект при аварии: «да» забирается один раз, а случилось ли действие при сбое посередине,
  неизвестно.
- Защиты от кода навыка, который действует вне ручек: в `ready()`, `contexts()`, своих командах.
- Жёсткого обрыва ручки: `SIGALRM` срабатывает между инструкциями Python, а не посреди операции в C.
- На Windows — немедленной остановки ручки: срок ручки обеспечивает прерывание исполняющегося Python-кода при
  обработке прерывания интерпретатором. Блокирующие операции могут задержать прерывание; автор ручки обязан
  задавать им конечные таймауты. Гарантия немедленной остановки произвольного кода отсутствует.

## Платформы

Каркас — для разных ассистентов; работают они чаще всего на сервере или в контейнере, а Windows и macOS для
большинства — среда разработки (решение владельца 08.11.2026). Поэтому гарантии этого документа полностью обещаны
для **Linux**. Локальный прогон на Windows или macOS их не доказывает: управление процессами, права, остановку и
батарейки ОС проверяют в своей среде — Linux CI или контейнере.

| | Linux | macOS | Windows |
|---|---|---|---|
| Срок ручки | `SIGALRM`: прерывает и ожидание, которое ОС прерывает сигналом | как Linux | прерывание главного потока: исполняющийся Python-код — да, блокирующая операция — после своего конца (см. выше) |
| Остановка дерева программ | всё дерево, группы процессов, сеанс — признак отделённого | как Linux | всё дерево (`psutil`), но сразу, без просьбы (TERM там — TerminateProcess), и **отделённое не различается**: браузер или приложение, открытые `launch`, останавливаются вместе с поручением |
| `stop` из другого терминала | сигнал держателю фразы — фраза выходит сама, отмена в журнале | как Linux | процесс фразы завершается сразу, без записи об отмене; Ctrl+C в своём терминале — как Linux |
| Файлы ассистента закрыты | `0600`/`0700`, проверяет E015 | как Linux | папки в профиле пользователя (его закрывает Windows); E015 проверяет только место |
| Батарейки `voice`, `tasks`, `notify`, `desktop` | да | нет | нет |

Личный ассистент у клиента прямо на Windows допустим, если у его навыков ограниченные ожидания и проверенная
отмена: важен состав поставки, а не только то, что каркас запускается. Полные гарантии на Windows (ручка в отдельном
процессе, свои права доступа) — отдельная работа под такого клиента.
