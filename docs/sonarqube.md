# SonarQube: что разрешено намеренно и почему

Каркас проверяет SonarQube Cloud (Automatic Analysis). Здесь — решения, которые переживают отдельный анализ:
почему часть предупреждений не исправляется, а принимается или считается ложной. Поштучный разбор конкретного
среза (ключи находок, номера строк) в репозиторий не кладётся — он устаревает с первым коммитом в эти файлы.

Правило: находку не подавляют `NOSONAR`, не отключают правило и не исключают исходники ради рейтинга.
Исправляется реальный дефект; остальное — статусом в Sonar с причиной из этого файла.

## CI: сборка при установке (S8541) и незапертые версии (S8544)

**Граница доверия.** `ci.yml` и `platforms.yml` запускаются на `push` в `main` и на `pull_request`, без
`pull_request_target`; `permissions: contents: read`, секреты в шаги не передаются, деплоя и общего кэша сборки
с привилегированным запуском нет. PR намеренно исполняет изменённый код и его build backend — иначе изменение
не проверить. `actions/checkout` и `setup-uv` закреплены по SHA, версия uv — точная.

**Что зафиксировано.**
- `uv.lock` запирает версии и хеши зависимостей каркаса; шаги после `uv sync --locked` запускаются
  `uv run --no-sync` — проверяется установленное окружение без скрытой повторной синхронизации.
- Инструменты вне lock — с точной версией: `uvx basedpyright@…`, `uvx ruff@…`, `pytest==…` в чистом окружении
  wheel. Транзитивные зависимости этих инструментов не заперты — остаточный риск принят для одноразового
  read-only CI.

**Что разрешено намеренно.**
- `uv sync` / `uv sync --locked` каркаса — собирает сам каркас; build isolation берёт `uv_build` по диапазону из
  `pyproject.toml`, lock его не запирает. Сборочный код зависимости остаётся доверенным — принятый риск.
- `uv sync` проекта из образца — без `--locked`: lock-файла у нового проекта ещё нет, и CI проверяет ровно путь
  пользователя — свежее разрешение зависимостей из шаблона.
- `uv pip install dist/*.whl` — установка собранного wheel с runtime-зависимостями без dev и extras: так видно,
  что в дистрибутиве нет пропущенных файлов и обязательного импорта необязательной библиотеки.
- `uv pip install --no-deps -e .` нового проекта — editable-сборка самого проекта; установленный каркас не трогает.

Массовое `--no-build` сломало бы смысл этих шагов: каркас и новый проект действительно нужно собрать.

**Ложное.** Команды `uv run … --no-project` не синхронизируют и не собирают проект — проекта у них нет; uv сам
предупреждает, что `--no-sync` рядом с `--no-project` без эффекта, поэтому флага там нет.

## S930: `_thread.interrupt_main(signum)` — ложное

Аргумент `signum` поддерживается с Python 3.10
(<https://docs.python.org/3.14/library/_thread.html#_thread.interrupt_main>); каркас требует 3.14. Аргумент
нужен: отдельный сигнал отличает срок ручки от Ctrl+C пользователя (`core/tools/deadline.py`).
`.sonarcloud.properties` задаёт `sonar.python.version=3.14` — Automatic Analysis читает этот файл, а не
`sonar-project.properties`. Если правило всё равно срабатывает — статус False positive с этой причиной.

## Path Traversal (S8707, S2083): граница доверия CLI

Предупреждения о путях из аргументов командной строки и из содержимого файлов относятся к локальным
инструментам владельца, а не к входу от модели или по сети.

| Где | Путь откуда → куда | Почему не уязвимость |
|---|---|---|
| `scripts/demo_cast.py` | аргумент → файл записи | генератор демо запускает автор и сам выбирает файл; нет HTTP-входа, повышения прав или обещанного каталога вывода |
| `modules/tasks/peek.py` | аргумент → чтение очереди | путь передаёт таймер из конфигурации владельца; наружу отдаётся только код выхода «есть ли работа» |
| `core/management/scaffold.py`, `_list_in_guide` | `SKILL.md` → тот же `SKILL.md` | содержимое файла меняет только строку шапки и никогда не становится путём записи |

`Scaffold` — генератор доверенного проекта, а не песочница файлов и не ручка модели. Имена навыка и ручки
проверяются (`_check_name`: латинские строчные, цифры, `_`), поэтому `../x` не уводит запись за папку навыков.
Если генератор станет доступен недоверенному входу (API, ручка модели), эту оценку нужно пересмотреть: тогда
нужен договор корней записи и защита ссылок.
