# Как предложить изменение

Спасибо, что заглянули. Это личный проект: отвечаю по возможности. Перед большой правкой лучше открыть issue и
договориться — так меньше шанс, что работа пропадёт.

## Порядок

1. `uv sync --all-extras` и один раз `git config core.hooksPath .githooks` — хук перед коммитом гоняет тесты,
   типы и линтер.
2. Правила устройства — в [AGENTS.md](AGENTS.md): ограничение держит код, а не текст для модели; новое правило для
   проектов приходит вместе с проверкой в `core/checks/` и строкой в `docs/checks.md`; каркас не знает слов
   предметной области; стандартное вместо самописного.
3. Новое поведение — с тестом. Изменение того, что ассистенты видят (публичные имена, настройки, договор ручки,
   коды проверок), — по [docs/stability.md](docs/stability.md): строка «Ломает:» или «Строже:» в `CHANGELOG.md`.
4. Решение, которое меняет устройство или обещания каркаса, — строкой в [docs/decisions.md](docs/decisions.md) в
   том же коммите.

## Стиль

- Код — Python 3.14, типы проверяет `basedpyright`, стиль — `ruff`.
- Имена в коде — английские; комментарии, docstring, документы и тексты для модели — по-русски, простыми словами.
- Один pull request — одна мысль.

## Безопасность

Об уязвимостях — не в issue, а как описано в [SECURITY.md](SECURITY.md).
